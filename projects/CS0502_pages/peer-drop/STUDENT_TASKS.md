# 项目三：同学快传 / PeerDrop

## 目标

制作一个简化版 LocalSend：两位同学在同一 Wi-Fi 或可信局域网中，可以通过浏览器互相发送一个文件。

本项目不提供具体提示词、接口或参考实现。你需要自行与 AI coding agent 协作，决定技术路线、拆分任务、测试和修复问题。

## 基础要求

1. **真实跨设备传输**：发送端和接收端必须是两台独立设备；手动输入接收端 IP 地址与端口即可，不要求自动发现。
2. **文件选择与确认**：发送端选择一个文件，接收端能看到文件名和大小，并能接受或拒绝。
3. **配对码**：发送端显示一次性配对码；接收端必须输入正确配对码才能开始接收。
4. **传输状态**：双方必须显示等待、传输中、成功、失败或拒绝等清晰状态；传输中应显示进度或已传输字节数。
5. **完整性校验**：传输完成后计算并比较文件的 SHA-256 值，明确显示“校验通过”或“校验失败”。
6. **文件保存**：接收端将文件保存到一个明确的下载目录，并显示最终保存位置。
7. **错误处理**：至少处理错误地址/端口、配对码错误、接收方拒绝、网络中断或文件过大中的三种情况。

## 范围边界

- 仅需支持一次发送一个文件。
- 不要求公网部署、自动局域网发现、端到端加密、断点续传或账户系统。
- 配对码用于确认双方正在配对，**不等同于加密**；请在报告中说明这一点。
- 不要在公共 Wi-Fi 或公网环境测试；不要传输敏感内容。

## 需要说明的计算机系统概念

在报告或演示中解释：

- IP 地址与端口分别解决什么问题；
- 浏览器、发送端服务、接收端服务分别扮演什么角色；
- 文件如何从发送端磁盘读出、经网络传输、写入接收端磁盘；
- SHA-256 如何用于检查完整性，以及它不能保证什么；
- 一次性配对码提供了什么保护，又不提供什么保护。

## 提交内容

1. 可运行的完整项目文件夹或 ZIP；
2. 60–120 秒演示视频：两台设备完成一次真实传输，并展示 SHA-256 校验；
3. README：启动步骤、测试网络环境、已知限制；
4. 简短迭代记录：你如何让 AI agent 帮助你推进、遇到的一个问题及修复方式。

## 加分项

- 自动发现可信局域网内的接收端；
- 文件类型或大小限制；
- 配对码超时失效；
- 传输历史；
- 多文件队列；
- 显示传输速度与预计剩余时间。
